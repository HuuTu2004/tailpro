# Kubernetes ingestion: scoped CLI decision and limits

Research checked **2026-11-25**, for phase **6.12.1–6.12.4**. This records upstream facts and TailPro design requirements; it is not a runtime compatibility claim. Sources are official Kubernetes documentation and the pinned upstream **v1.35.0** source. Actual client/server versions still require acceptance evidence. Scope follows [phase 6](../plan/phase-06-universal-log-ingestion.md) and [contracts](contracts.md).

## Decision

**Design:** use the existing SSH command transport with a dedicated `kubectl` adapter for one explicitly selected context, namespace, Pod and container instance. Reuse the payload/framing pipeline. Initially reject credential `exec` and legacy `auth-provider` configuration; support only the selected trusted configuration's non-plugin credentials. Native API remains a future option: it improves structured errors and cancellation but does not add a UID precondition to the standard Pod logs endpoint.

Do not claim complete Kubernetes history or atomic instance selection. The CLI approach is acceptable for a trusted remote account/configuration, with the identity and mutable-configuration limitations below exposed. It does not isolate TailPro from a compromised SSH account, executable, kubeconfig, or cluster.

## Upstream facts

| Area | Evidence and consequence |
| --- | --- |
| Selection | A kubeconfig context groups cluster, namespace and user. Default behavior uses current-context; `KUBECONFIG` can name merged files. Kubernetes warns crafted kubeconfigs can execute code or expose files. Explicit context and namespace prevent accidental ambient selection, but do not establish trust. [Kubeconfig](https://kubernetes.io/docs/concepts/configuration/organize-cluster-access-kubeconfig/) |
| Pod identity | Names can be reused after deletion; UIDs identify distinct objects. Store namespace + Pod name + UID, not name alone. [Names and IDs](https://kubernetes.io/docs/concepts/overview/working-with-objects/names/) |
| Container instance | `ContainerStatus.containerID` includes the runtime prefix. `restartCount` can reset to zero after node state loss. `lastState.terminated.containerID` identifies a reported previous attempt. Missing IDs or status must produce unavailable/unknown identity, not an invented attempt. [ContainerStatus and terminated state](https://kubernetes.io/docs/reference/generated/kubernetes-api/v1.35/#containerstatus-v1-core) |
| Logs selection | The logs GET path is namespace + Pod **name**, with a container query parameter. It accepts no Pod UID, container ID, restart-count or resource-version precondition. `previous` selects previous terminated logs; timestamps are RFC3339/RFC3339Nano. `limitBytes` can cut a final line and return slightly more/less than requested. Therefore request completion is not a byte-exact checkpoint. [Pod log API](https://kubernetes.io/docs/reference/kubernetes-api/core/pod-v1/#get-read-log) |
| CLI switches | `--follow` streams; `--previous` requests the previous instance if available; `--timestamps` prefixes each line. `--since-time` is RFC3339 and mutually exclusive with `--since`. `--tail=-1` requests all available lines without selectors; selectors change the default to 10. `--limit-bytes` defaults to unlimited. Neither `--since-time` nor timestamps supply an event cursor. [kubectl logs](https://kubernetes.io/docs/reference/kubectl/generated/kubectl_logs/) |
| History | Kubelet ordinarily retains one terminated container's logs; eviction removes associated containers and logs. Only the latest rotated log file is available through `kubectl logs`. Timestamp overlap cannot recover older rotated/deleted files or skipped restarts. [Logging architecture](https://kubernetes.io/docs/concepts/cluster-administration/logging/#log-rotation) |
| RBAC | Pod reads and the `pods/log` subresource are distinct permissions. Minimum selected-Pod operations require core-group `get` on `pods` and `pods/log`; a namespaced Role can restrict `resourceNames` to the Pod name. List/watch discovery requires additional verbs; this adapter must not assume them. RBAC name restrictions do not bind a UID or container. [RBAC resources and subresources](https://kubernetes.io/docs/reference/access-authn-authz/rbac/#referring-to-resources) |
| Credential execution | A selected user's `exec` command can receive arguments, environment and optional cluster information. Relative commands resolve from the kubeconfig directory. Closing stdin prevents interaction, not execution: `Never` and `IfAvailable` plugins can run without stdin. [Credential plugins](https://kubernetes.io/docs/reference/access-authn-authz/authentication/#client-go-credential-plugins) |

## What `config view` actually does

**Verified source:** `kubectl --context=<selected> config view --raw --minify -o json` loads configuration, sets the requested current-context before minifying, optionally flattens, converts, then prints. It does not construct a REST client or call credential plugins along this command path. `--raw` suppresses secret redaction; `--minify` is selection, not sanitization. `--flatten` also bypasses the redaction branch. [view.go, v1.35.0](https://github.com/kubernetes/kubernetes/blob/v1.35.0/staging/src/k8s.io/kubectl/pkg/cmd/config/view.go#L123)

The loader calls `RawConfig()`, which loads/merges config and returns the stored configuration rather than invoking `ClientConfig()`. This supports inspecting `exec`/`auth-provider` before an authenticated operation for the inspected version. It is not a guarantee about arbitrary replacement binaries or every future kubectl version. [PathOptions](https://github.com/kubernetes/kubernetes/blob/v1.35.0/staging/src/k8s.io/client-go/tools/clientcmd/config.go#L88), [deferred RawConfig](https://github.com/kubernetes/kubernetes/blob/v1.35.0/staging/src/k8s.io/client-go/tools/clientcmd/merged_client_builder.go#L55), [direct RawConfig](https://github.com/kubernetes/kubernetes/blob/v1.35.0/staging/src/k8s.io/client-go/tools/clientcmd/client_config.go#L120)

Flattening reads referenced client certificate, client key and CA files into memory; it does **not** inline `tokenFile`. A fingerprint of flattened JSON therefore misses token-file content changes. Loading also has legacy config-file migration behavior; describe inspection as avoiding authentication execution, not as universally having no filesystem effects. [FlattenConfig](https://github.com/kubernetes/kubernetes/blob/v1.35.0/staging/src/k8s.io/client-go/tools/clientcmd/api/helpers.go#L105), [loading rules](https://github.com/kubernetes/kubernetes/blob/v1.35.0/staging/src/k8s.io/client-go/tools/clientcmd/loader.go#L98)

## Adapter requirements

These are **TailPro requirements/inferences** from the facts above:

1. Resolve the remote account's configured kubeconfig inputs; pin selected context + namespace on every request. The user must select one explicit absolute kubeconfig path; ambient multi-file KUBECONFIG discovery is not used. Bound config JSON before parsing. Disable ambient kubectl preferences where supported; do not accept user-supplied extra CLI flags.
2. Inspect selected configuration before any authenticated GET/logs call. Reject `exec`, `auth-provider`, insecure TLS, and unexpected impersonation/endpoint changes. Require HTTPS and keep API-server and kubelet certificate verification enabled. Keep raw configuration, tokens, certificates/keys and full diagnostics out of logs, persistence, UI and MCP; expose only a bounded safe capability result and internal fingerprint.
3. A preflight fingerprint followed by another kubectl invocation using mutable inputs has a **TOCTOU window**: kubectl rereads configuration and referenced files. Rechecking detects changes afterward; it cannot prevent a newly inserted credential plugin from executing in the intervening authenticated invocation. Trusted mutable remote config is an explicit initial limitation. A hard no-plugin execution guarantee requires every request to use an immutable validated configuration/credential snapshot or equivalent enforced execution isolation. A snapshot design must also handle referenced files, token refresh and secret cleanup.
4. GET only the named Pod; match selected UID and named container status/ID/restartCount before opening logs. Pin `--container`, `--context`, `--namespace`; never use selectors, all containers, workloads, namespace enumeration, exec, attach, port-forward or node filesystem fallback. Keep stdout payload separate from bounded stderr diagnostics.
5. Revalidate identity immediately after opening and at bounded intervals (initial design: **2 seconds**), plus reconnect/end. On mismatch/unknown identity, stop the owned reader, emit generation gap/uncertainty, and require explicit reselection for a recreated Pod. Polling cannot prove atomic instance attribution; a restart/name-reuse race can occur between GET and logs or between polls. Every affected interval retains that uncertainty.
6. Current follow uses `--follow --timestamps --tail=200` for an explicit bounded initial recent window; an explicit prior-time request uses validated `--since-time`. Previous logs are a separate bounded snapshot with `--previous`, checked against reported terminated identity; do not treat previous as arbitrary restart history. Apply source admission/backpressure and process-tree cleanup budgets. A server byte cap does not replace local bounds.
7. Reconnect with timestamp overlap and replay evidence; never silently discard equal timestamps, synthesize exact offsets, infer completeness from EOF, or parse the API output as raw CRI records. Surface denied/unavailable, rotation/history uncertainty, restarts, recreation and disconnect gaps through application/UI/MCP coverage.

Manual acceptance still needs multi-container selection, RBAC denial, UID recreation, container restart/reset, previous availability, rotation, config mutation, cancellation and disconnect on recorded real versions. No automated tests were added or run for this research-only document.

## Implemented snapshot boundary

The helper flattens the selected configuration into a sealed Linux memfd and passes only `/proc/self/fd/<fd>` to authenticated kubectl operations. It rejects exec/auth-provider/tokenFile, impersonation and insecure TLS; referenced certificate/key/CA data is embedded by flattening. Every authenticated operation uses that immutable snapshot, with `KUBECTL_KUBERC=false`, explicit context and namespace, and no extra caller flags. Secret configuration is not written to disk or returned to the UI. The source requires a digest and explicit trust after inspection. Mutable original configuration is rechecked during follow; changes stop the source and require another inspection. This addresses the configuration-reopen execution window described above; it does not eliminate compromised executables/accounts or the name-based Pod logs API race.

Local evidence uses simulated CLI responses, including plugin rejection before authenticated requests, config digest mismatch, selected instance restart, previous logs and child cleanup. This is not real-cluster acceptance or compatibility certification for every kubectl version. Dynamic credential refresh, token files, init/ephemeral containers and arbitrary historical instances are Unsupported in this implementation.
